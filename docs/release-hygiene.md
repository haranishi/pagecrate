# 公開前の点検

コードを公開する前、PR を作る前、マージする前に、秘密・個人や会社の情報・アカウントの識別子が公開の対象に無いことを確かめ、結果をこの文書の表に残します。点検が終わっていないあいだと、見つかった問題が解決していないあいだは、リポジトリの公開・PR のマージ・本番への反映をしません。

## 点検するもの

| 種類 | 例 | 主に見る場所 |
|---|---|---|
| 秘密 | API の鍵、トークン、署名鍵、`.dev.vars` の実の値 | 作業ツリー、Git の履歴の全体 |
| 個人の情報 | 氏名、住所、電話番号、私用や所属先のメールアドレス | 文書、コミットの作者、試験の固定データ |
| 会社・取引先の情報 | 社名、案件名、社内の URL | 文書、作業のメモ |
| アカウントの識別子 | Cloudflare の account_id、workers.dev のサブドメイン、検証用の Worker の名前、配置した版の ID、クラウドのプロジェクト ID | 設定ファイル、文書、スクリプト |
| 手元の情報 | ローカルの絶対パス、手元のユーザー名 | スクリプト、作業の記録 |
| 画像・動画の付帯情報 | EXIF・XMP、撮影した位置、作者の名前、作成に使ったソフトの名前 | `public/`、`fixtures/`、撮り直した素材 |

公開しないもの（作業の記録、調査のメモ、評価に使った画像、検証用の道具）が、公開する木に入っていないことも確かめます。

## なぜ「掃除した新しい履歴」で公開するのか

古いコミットには、いまの作業ツリーから消した識別子が残っていることがあります。履歴を書き換えて消す方法は強制的な push を伴い、しかも複製や取り込み済みのコピーには古い中身が残ります。取り返しがつかないので、この方法は採りません。

代わりに、点検した作業ツリーのスナップショットだけを、新しい履歴を持つ公開リポジトリとして出します。元の非公開リポジトリは書き換えず、控えとして残します。公開は運営者の個人のアカウントで行い、会社のアカウントには置きません。

## 道具

点検は四つを組み合わせます。自動の検査、公開用スナップショットの道具、実装とは別の担当による読み取りだけの独立レビュー、運営者本人の最終確認です。

- `npm run hygiene`：秘密・手元のパス・個人の NG ワード・アカウントの識別子・メールアドレス・画像と動画の付帯情報を、1コマンドでまとめて調べる。見つけた値は出力にも記録にも出さず、ファイル・行・種類だけを出す。個人の NG ワードは非公開のファイル（`.precheck-ng.txt`）に置き、リポジトリには入れない。`--profile private-pr`（既定。非公開リポジトリへ commit するとき。公開しないフォルダは秘密の検査だけ）、`--profile public`、`--tree <フォルダ>`（公開用の木の点検）がある。設定は `scripts/hygiene.config.json`（公開しないフォルダの一覧の唯一の正本と、ファイル単位の例外）
- gitleaks：`hygiene` が呼ぶ。作業の木と Git の履歴の全体から秘密を探す
- `npm run snapshot -- --out <空のフォルダ>`：公開するものだけを、許可の一覧（名前を挙げたファイルとフォルダ）から新しい木に書き出し、`LICENSE`（MIT）と `THIRD_PARTY_NOTICES.md` を作り、その木に点検をかけて、木の指紋を記録する。運営者の名称が未確定なら、非0で止まる
- `npm run release-gate`：公開してよいかを、条件ごとに PASS／FAIL で判定する。デモだけ公開の条件と、実サイトの取得を開く条件（弁護士と Cloudflare の確認の記録など）に分かれる

ビルドの生成物（`.next/`・`.open-next/`）は公開の対象外です。生成されたコードに秘密の検出が反応することがありますが、公開の判断には使いません。

## 手順

1. 作業ツリーと履歴の全体に自動の検査をかけ、画像・動画の付帯情報を調べる
2. 独立レビューに、識別子の値を伏せた形で結果を渡す
3. 運営者本人が結果を確かめる
4. 問題が見つかったら公開を止める。場所と対処（削除・置換・公開の対象から外す）を記録し、対処のあとに点検をやり直す
5. 公開用のスナップショットを作ったら、その木にもう一度すべての検査をかける
6. フォルダごと許可している `src/`・`tests/`・`docs/`・`public/`・`fixtures/`・`.github/` の中は、置いたファイルがすべて公開される。スナップショットの記録の一覧（`manifest`）を運営者が目で見て、私的なメモや保存した他人のページが無いことを確かめる

記録には識別子の値を書かず、場所と種類だけを書きます。`LICENSE` と第三者の表記がそろっていることも、公開の条件に含めます（[依存のライセンスと同梱の素材](licenses-and-assets.md)）。
