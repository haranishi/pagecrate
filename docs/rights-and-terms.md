# 権利・規約・個人情報の確認結果

確認日：2026-11-01。この文書は法的な助言ではありません。運営者が弁護士の確認を受ける前に、論点を整理したものです。原文で確かめた事実と、そこからの読み取り（解釈）を分けて書き、調べていないことは「未確認」に置きます。調べていないことを「問題なし」とは書きません。

## 結論

- 最も議論になりうるのは、**運営者のサーバーが第三者の画像・動画を取得し、ZIP にして利用者へ送る**という形そのものです。最高裁の判例の考え方では、利用者が指示していても、サービスの提供者が複製の主体とみなされることがあります。この形が適法かどうかは、ここでは判断しません。公開の前に専門家の確認が要ります
- Cloudflare の契約は「VPN その他の類似のプロキシサービス」の提供を禁じています。他人のサイトを取得して中継するこの製品が当たるかは、確認が要ります
- 個人情報は、IP アドレスを保存しない作りで、個人データを持たない設計と読めます。ボット確認で Cloudflare に情報が渡る点は、電気通信事業法の外部送信規律が適用されるかどうか自体が未確認です
- 利用規約には、免責・準拠法・管轄・変更の手続・合意の取り方が欠けています

依存のライセンスと同梱の素材の出どころは [licenses-and-assets.md](licenses-and-assets.md) に分けました。

## 対象サイトの規約：運営者は確かめられない

利用者が入れるサイトごとの規約を、運営者は前もって確かめられません。画面は URL 欄の直下に「取得できても、再利用の許諾ではありません。使う前に、権利者の許諾と対象サイトの規約を確認してください。」を常に出し、規約とポリシーにも同じ趣旨を書いています。再利用の判断が利用者にあることは、これで伝わります。足りない点は四つです。(1) 注意は再利用についてで、取得そのもの（自動の取得や保存を禁じるサイト）に触れていない。(2) 取得先から見て、要求が利用者でなく PageCrate のサーバーから来ることを伝えていない。(3) 注意書きは、運営者が複製や送信の主体とされた場合の責任を消さない。(4) サイトの運営者が取得を断る経路は、窓口（未確定）と拒否ドメインの設定だけで、robots.txt は読まない。

## 利用規約の本文に無いもの（専門家の確認で決める）

規約（`src/lib/policy-content.ts`）には、できること、再利用の許諾ではないこと、禁止事項（権利の侵害、制限の回避、秘密のリンクや個人情報の入力、過大な負荷とボット確認・回数制限の回避）、量の上限、停止と終了、運営者と窓口、版の更新があります。次は書かれていません。この担当では本文を変えていません。

- 免責と責任の制限。消費者契約法8条は、事業者の損害賠償の責任の全部を免除する条項などを無効とする（https://laws.e-gov.go.jp/law/412AC0000000061 ）
- 準拠法と管轄
- 変更の手続。民法548条の4は、定型約款の変更に効力の発生時期と周知を求める（https://laws.e-gov.go.jp/law/129AC0000000089 ）。いまは「版を更新します」だけ
- 規約への合意の取り方。確認の画面はプライバシーポリシーを読んだことだけを確かめ、規約に触れない。定型約款の合意（民法548条の2）の要件に照らして確かめる
- 不正アクセスの明示的な禁止（いまは「制限をくぐり抜けようとすること」）、違反したときの措置、対象の地域と年齢、権利者の申し立ての手続
